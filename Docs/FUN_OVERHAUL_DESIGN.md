## 1. 규칙 변경 (양판 공통 계약)

### R1. 보스 곡선 정상화
- `finals`(기말고사): `quotaMul` 1.0 → **1.15**. desc: `스핀+1 · 요구치 ×1.15 · 막스핀 EXP ×2 · 첫스핀 -10%`.
- `strict`(꼰대교수): 같은 심볼 3개↑(`bestSetCount >= 3`) **있으면 ×1.15**, 없으면 **×0.75**(기존 ×1 / ×0.5).
  note: `👨‍🏫 3매치 ×1.15` / `👨‍🏫 3매치 없음 ×0.75`. desc: `스핀+1 · 같은심볼 3개↑ ×1.15 / 없으면 ×0.75`.

### R2. 요구치 곡선 재조정 (일반 모드만)
- 일반 모드 `QUOTAS` = `[90, 105, 125, 145, 190, 200, 240, 285, 340, 400, 475, 560, 660, 780, 1050]` (최종 — 초안은 S5 165·S15 920, §5 튜닝으로 변경),

- **심화 모드는 기존 표 그대로** — `QUOTAS_DEEP = [110,120,130,140,150,170,200,235,280,330,390,460,540,640,755]`
  + ×1.2 를 별도 상수로 보존하고 `quota(stage, deep)` 가 분기한다(심화 밸런스·하니스 기준선 보호).
  심화 난이도 조정은 R8(튜닝 단계)에서 측정 후 결정.

### R3. 홀드(HOLD) — 스핀마다 생기는 결정 (일반 모드만)
- 스테이지 시작 시 `holdCharges = 1`(누적 없음, 매 스테이지 1로 리셋).
- 스핀이 끝난 뒤 다음 스핀이 남아 있으면(SPIN 페이즈), 플레이어는 **릴 칸을 최대 2개** 탭해 홀드 토글할 수 있다
  (`holdCharges >= 1` 일 때만). 홀드 표시는 다음 스핀 버튼을 누를 때까지 자유롭게 켜고 끌 수 있다.
- 홀드가 1칸 이상 켜진 상태로 스핀하면: 그 칸들은 **직전 스핀의 원시 착지 심볼(raw, 폭탄/자석 변형 이전)**
  을 그대로 유지하고 나머지 칸만 새로 굴린다. 이 스핀에서 `holdCharges -= 1`, 홀드 표시는 해제된다.
- 예언(oracle, `lockedNext`)이 확정돼 있으면 홀드 불가(토글 시 토스트). 홀드 스핀에는 아이템 칸조작(cellOps)
  을 같이 쓸 수 있다(홀드 적용 → cellOps 순서).
- 릴 칸 수가 바뀌는 경우(보조릴 등)에는 인덱스가 범위 밖인 홀드는 무시한다.
- 새 아이템/장치 연동(이번 개편 범위): **집중(FOCUS) 특수스핀이 홀드 충전 +1** 을 추가로 준다(R6).

### R4. 피버 게이지 (일반 모드만, 심화 피버와 별개 필드)
- `feverGauge`(0~100) — 스핀마다 그 스핀의 `bestSetCount` 기준으로 충전: 2개 +5 · 3개 +15 · 4개 +35 · 5개 +60.
  런 내내 유지(스테이지를 넘어 이월).
- 100 이상이 되면 즉시 `feverSpins = 3` 을 세팅하고 게이지 0(넘친 양은 버림). 다음 스핀부터 3스핀 동안
  **최종 EXP ×1.5**(보스·특수스핀 적용 후 마지막 곱). 피버 중에는 게이지가 차지 않는다.
- 스테이지가 피버 도중 끝나도 남은 피버 스핀은 다음 스테이지로 이월.
- note: `🔥 피버 ×1.5 (남은 N)`. 상태 노출: `feverGauge`, `feverSpins`.
- 심화 모드(deepMode)에서는 이 시스템이 동작하지 않는다(기존 심화 피버만).

### R5. 앵콜(ENCORE) — 클리어 점수 더블업 (일반 모드만)
> 2026-10-28 재설계(리드 결정): 구안(판돈 100점 고정 + 스핀 점수×배율 적립)은 스핀 점수 평균이 ~20점이라 −EV 가 심해 폐기.
- 스테이지를 **남은 스핀 1개 이상**으로 클리어하고 이번 스테이지 **클리어 점수 `stake` > 0** 이면(`STAGE_CLEAR`),
  노드로 가기 전에 `[정산하고 진행]` 또는 `[앵콜 스핀]` 을 고를 수 있다. `stake` = 클리어 순간 지급된 이번 스테이지 클리어 점수 합계
  (`clearSummary.gain` = stage×50 + 초과 EXP×2 + 남은 스핀×100 + 보스 500 + 연승 보너스). 빚문서 등으로 0이면 앵콜 불가.
- **첫 앵콜 스핀을 시작할 때** `stake` 를 run 점수에서 빼서 `pot = stake` 로 건다(점수가 `stake` 미만이면 시작 불가).
  앵콜 스핀 1회 = 남은 스핀 1개 소모 + 일반 굴림. 스핀의 EXP·점수는 버리고 **코인 수입만 정상 지급**.
- **성공**(페어 이상 AND 해골 2개 미만): `k += 1`, `pot = floor(stake × (1 + 0.5k))` (×1.5, ×2, ×2.5 …). 이어서 `[정산]` 또는 다음 앵콜.
- **BUST**(페어 없음 또는 해골 2개↑): `pot = 0` (건 판돈 포함 전부 소멸), 앵콜 종료.
- `[정산]` 을 누르거나 남은 스핀이 0이 되면 `score += pot` → 노드 선택으로. (`proceedToNodes` 도 진행 중인 앵콜을 먼저 정산)
- 앵콜 중에는 특수스핀·홀드·아이템 사용 불가, 피버 충전/소모 없음, 보스 규칙 미적용. 업적/해골/심볼 통계 추적 없음.
- 상태 노출: `encore: { available, active, k, pot, stake, lastBust, nextMul }` — `k` = 성공 횟수, `nextMul` = 다음 성공 시 `stake` 대비 배율.
  `C.ENCORE_STAKE` 상수는 삭제(`C.ENCORE_STEP` 0.5 만 사용).

### R6. 특수스핀 재설계 + 코인 소비처
- **올인(ALLIN)**: EXP **×2.5**, 해골 **1개 이상**이면 0(기존 ×2, 2개 이상이면 0).
  desc `EXP ×2.5 (☠ 1개라도 나오면 0)`.
- **집중(FOCUS)**: 하한 보장 페이스 ×0.6 → **×0.8**, 굴림 전 `rareWeightMul ×0.5` 패널티 **삭제**,
  발동 시 **홀드 충전 +1**(일반 모드). desc `최소 EXP 보장(페이스 80%) + 홀드 +1`.
- **스테이지당 종류별 1회 제한 → 반복 사용 허용, 비용 누진**: 같은 스테이지에서 같은 종류를 n번째 쓰면
  비용 = `cmdCoinCost(mode, boss) × n` (보스 +1·상한 5는 기본 비용에만 적용한 뒤 ×n). 최후(LAST)는 여전히
  마지막 스핀에서만(=스테이지당 사실상 1회). "런 단위 종류별 첫 1회 무료" 규칙은 유지.
  UI 버튼에 현재 비용 표시.
- **보조릴(dev_subreel)**: 최종 EXP -30% → **-15%**, desc 갱신.

### 5.6 앵콜(클리어 점수 더블업) 관찰

- 정책: 앵콜 가능하면 1회 시도 후 성공 시 즉시 정산. 클리어 스테이지의 **68.2%** 에서 시도(16231/23811), 스핀당 **BUST 27.8%**.
- 이론 EV = 0.722 × (1.5−1) − 0.278 × 1 = **+8.3%** (stake 대비). 실측 시도당 평균 순손익/stake **+8.3%**(합계 기준 +9.5%): 스테이지 구간별 S1~5 +8.0% · S6~10 +9.0% · S11~15 +9.6% · S16+ +11.9%.
- 시도당 평균 판돈 1187점·평균 순이익 +112점, 시도 1회 BUST 시 판돈 전액 손실. 앵콜이 런 점수에 주는 평균 기여는 약 +910점/런(평균 최종 점수 29,020 의 ~3%).
- ⚠ 판돈은 `초과 EXP×2` 항 때문에 후반 스테이지에서 급증한다(S16+ 평균 4,555점, 최대 256,828점 — 한 판 점수 변동폭이 커짐). 점수 랭킹 균형이 걱정되면 `ENCORE_STEP` 또는 판돈 상한을 `data.js C` 에서 조정(코드 수정 없이 가능한 건 `ENCORE_STEP` 뿐).
- 앵콜은 EXP 를 버리고 남은 스핀을 쓰므로 생존율 지표에는 영향이 없다(RNG 소비만 달라짐).

### 5.8 구현상 합의/주의 (U1 이식용)

- 새 배율 곱은 부동소수 오차 때문에 **`floor(v × m + 1e-9)`** (`E.mulFloor`)를 쓴다 — `floor(100 × 1.15)` 가 114 가 되는 것을 방지(C# 도 같은 보정 필요). 앵콜 `pot = mulFloor(stake, 1+0.5k)`.
- 특수스핀은 `usedCmds` 에 기록하지 않고 `cmdUses`(스테이지 내 종류별 사용 횟수)로 누진 비용을 계산한다. 비용 = `cmdCoinCost(종류, 보스) × (1 + CMD_COST_STEP × (n−1))`, 런 첫 사용 무료권은 유지.
- 앵콜: `stake` 는 `_clearStage` 의 `gain`(= `clearSummary.gain`)을 `encoreStake` 에 저장. 첫 앵콜 스핀에서 `score -= stake; pot = stake`, 성공 시 `encoreK += 1; pot = mulFloor(stake, 1 + 0.5×encoreK)`,
  BUST 시 `pot = 0`(판돈 포함 소멸). 진행 중(`active`)에는 점수가 stake 보다 적어도 계속 가능. 앵콜 스핀은 `_trackSpin`·해골/심볼/도감 통계·불운 게이지를 건드리지 않는다(코인 수입만 지급).

## 6. 리드 결정 (1차 검수 반영, 2026-10-28)

- **S5 탐욕 봇 98.1%** — 허용. 첫 보스는 입문용(단순 봇 78.4%)이 우선이다.
- **곡선 단조**는 `QUOTAS` 표값 기준이다. 보스 배율(finals ×1.15)을 곱한 실효 요구치는 S5 > S6(novice 201 > 184)이 되는데,
  "보스 스테이지가 바로 다음 일반 스테이지보다 빡세다"는 의도된 결과다.
- **피버 게이지와 재굴림/조작/재시험**: 게이지 충전·발동은 그 스핀의 **최초 굴림 결과** 기준으로 한 번만 정해지고,
  재굴림·조작으로 결과가 바뀌어도 다시 계산하지 않는다(이미 적용된 ×1.5 는 유지). 양판 동일.
- **연출 기준**: 기대감 = 앞 칸 같은 값심볼 3개↑, 니어미스 = 기대감 + 4매치 실패 + 마지막 릴이 그 심볼이 아님(양판 동일).
- **유니티 기존 이탈 3건을 웹 채택으로 해소**: EXP 후처리 순서(보스 → 특수스핀), 불꽃 다음 스핀 −50%, 기도 보정 임계
  (`WEB_PARITY_DESIGN.md` §2-(JJ)).
- **랭킹**: 개편으로 점수 분포가 달라졌다(앵콜·요구치). 기존 랭킹 노드는 그대로 두며, 시즌 분리 여부는 사용자 결정 사항으로 남긴다.
